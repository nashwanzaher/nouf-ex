### 18.1 Sentry wire-up

- `initSentry()` called in `__isMainModule` block, after OTel init
  (so the Sentry event carries the OTel `trace_id`).
- `sentryHandlers.requestHandler()` mounted before `requestId` so
  every request gets a `sentry-trace` breadcrumb.
- `sentryHandlers.errorHandler()` mounted before the project
  `errorHandler` so Sentry sees the original exception (and the
  fallback envelope doesn't trigger a second one).
- `flushSentry(2000)` called first in `gracefulShutdown` with a
  tight deadline — we'd rather drop events than block shutdown.

All sentry helpers (`captureWorkerError`, `captureMessage`,
`withSentry`) are **no-op when `SENTRY_DSN` is unset** (verified
in `tests/sentry.test.ts`).

### 18.2 OpenAPI 3.1 spec

- Uses **@asteasolutions/zod-to-openapi v8** (Zod 4 compatible)
  via the official `extendZodWithOpenApi(z)` patch.
- The registry is built **once at module-load** (no per-request
  cost) and served at `GET /api/openapi.json`.
- Swagger UI is loaded from `unpkg.com` (the standard host)
  via a tiny static HTML page in `lib/openapi-ui.html` — no 1.5 MB
  bundle in the API container.
- Each endpoint registration reuses pre-declared Zod schemas
  (`ErrorEnvelope`, `SuccessEnvelope`, `Pagination`, …) so the
  contract is a single source of truth: `validate()` and the
  OpenAPI doc cannot drift.
- Every public path is asserted by `tests/openapi.test.ts`:
  presence, OpenAPI version, security schemes, JSON-Schema dialect.

Documented endpoints:
- `GET /api/products` (filters + pagination)
- `GET /api/products/featured`
- `GET /api/products/deals`
- `GET /api/products/{id}`
- `GET /api/categories`
- `GET /api/stats/home`
- `GET /api/search` (with PG-FTS fallback contract documented in
  the `503` response)
- `GET /api/search/suggest`
- `POST /api/auth/login`
- `GET /api/health`, `GET /api/ready`, `GET /api/metrics`,
  `GET /api/openapi.json`

### 18.3 Degraded-mode contract tests

Pinned the documented fall-OPEN contract as runtime tests:

| Companion | Documented behaviour | Test |
|---|---|---|
| Redis | `cacheGet → null`, `cacheWrap → fetcher runs`, `rateLimit → middleware returns` | verified |

### 19.1 Contract testing

- The OpenAPI doc generated by `buildOpenApiDocument()` is the
  contract-of-truth. The `tests/contract/operational.contract.test.ts`
  file drives a minimal Express app (no DB, no auth) and
  validates every response against the published spec via
  `openapi-response-validator`.
- `$ref` resolution walks the doc's `components/schemas` tree
  so inline references resolve correctly.
- Status codes without a documented response shape (e.g. a 401
  on a path that only documents 200) pass without error —
  OpenAPI declares what IS typed, not what isn't.

### 19.2 Rate-Limit headers

```
RateLimit-Limit:     100
RateLimit-Remaining:  99
RateLimit-Reset:      60   ← delay-seconds, only on 429
Retry-After:          60   ← RFC 6585, only on 429
```

Happy-path responses emit only `Limit` + `Remaining` (Reset would
be misleading because the bucket rolls over continuously). On
429, all four headers are present.

### 19.3 API versioning (Stripe-style)

```
GET /api/products
Accept: application/vnd.noufex.v1+json   → 200 (v1)
Accept: application/vnd.noufex.v99+json  → 406 (with supported versions)
(no Accept header)                       → 200 (latest = v1)
Accept: */*, application/json            → 200 (latest)
```

Every response carries `X-API-Version: v1`. When a version is
deprecated, `Deprecation: true` is added; when it has a sunset
date, `Sunset: Sat, 01 Jan 2028 00:00:00 GMT` (RFC 8594 §4)
plus a `Link: <…>; rel="successor-version"` to the upgrade
guide.

### 19.4 Sentry → Alertmanager relay

- A 120-LOC Go reference implementation (`alertmanager-sentry-relay/main.go`)
  translates Sentry webhook payloads into Prometheus AlertManager v2
  alerts with a 10-minute dedup window.
- Severity mapping: Sentry `error`/`fatal` → `severity=page`,
  `warning` → `severity=warn`.
- The relay exposes `/health` + `/ready` for k8s probes and runs
  as a Distroless container (≈10 MB binary).
