# WCAG 2.1 AA — Accessibility Testing Standards

> **Audience:** everyone shipping a React component or page.
> **Last updated:** 2026-07-03 (P2-09).
> **Tooling:** [`vitest-axe`](https://github.com/chaance/vitest-axe) (axe-core) +
> [Testing Library](https://testing-library.com/) role queries.
> **Compliance target:** [WCAG 2.1 Level AA](https://www.w3.org/WAI/WCAG21/quickref/).

Accessibility is a **release gate**, not an aspirational note. The `a11y` step
in `.github/workflows/ci.yml` fails the build on any violation — there is no
`--continue-on-error` flag.

---

## 1. The four WCAG 2.1 principles (POUR)

Every test we write maps to one or more of these principles. They are the
spine of the WCAG standard:

| Principle       | Question it answers                              | Example rule      | What it prevents                           |
|-----------------|--------------------------------------------------|-------------------|--------------------------------------------|
| **Perceivable** | Can the user perceive the content?               | 1.4.3 Contrast    | Color-only status indicators               |
| **Operable**    | Can the user operate the interface?              | 2.4.4 Link Purpose| Vague link text like "click here"          |
| **Understandable** | Can the user understand the content/UI?       | 3.3.1 Error ID    | Unlabelled form errors                     |
| **Robust**      | Can assistive tech parse the content reliably?   | 4.1.2 Name/Role   | `<div>`-as-button without accessible name  |

Quick reference: <https://www.w3.org/WAI/WCAG21/quickref/?currentsidebar=%23col_overview&levels=aaa>

## 2. Our testing strategy

We defend accessibility with **three layers** — no single layer is enough:

### 2.1 Layer 1 — axe-core (automatic, via `vitest-axe`)

Catches ~30 rule families automatically: color contrast (where computable),
landmark structure, label/name mismatches, ARIA misuse, tab order, etc. Runs
on every render in the a11y suite.

```tsx
import { axe, toHaveNoViolations } from 'vitest-axe';
expect.extend(toHaveNoViolations);

const { container } = render(<MyPage />);
const results = await axe(container, axeOptions);
expect(results).toHaveNoViolations();
```

### 2.2 Layer 2 — role-based assertions (semantic regressions)

axe-core catches structure, but **not intent**. We pair it with Testing Library
role queries to assert the *semantic shape* we ship:

```tsx
// "OrderTimeline is a labelled list with 4 steps and aria-current on one"
expect(screen.getByRole('list', { name: /order progress/i })).toBeInTheDocument();
expect(screen.getAllByRole('listitem')).toHaveLength(4);
expect(screen.getAllByRole('listitem').filter(
  (el) => el.getAttribute('aria-current') === 'step',
)).toHaveLength(1);
```

This catches regressions that axe-core never sees — e.g. someone reverts the
semantic structure but keeps the visible UI intact.

### 2.3 Layer 3 — manual keyboard-nav review (PR checklist)

axe-core and RTL cannot simulate tab order or focus traps. The PR template
includes the line **"Tabbed through the affected screen — focus order is
intuitive, focus rings visible, modals trap focus."** Reviewers verify this
before merging a11y-touching PRs.

## 4. How to run

All commands run from [`app/`](../../../app/).

```bash
# All Vitest suites (includes the a11y tests)
npm test

# A11y tests only — fast (~1s)
npm run test:a11y

# Single a11y suite
npx vitest run src/pages/__tests__/a11y.test.tsx

# Coverage (includes a11y under the umbrella)
npm run test:coverage
```

In CI, the a11y step is the **second** run inside the `test` job
(`.github/workflows/ci.yml`):

```yaml
- name: Run vitest
  run: cd ${{ env.APP_DIR }} && npm test
- name: Run accessibility (a11y) tests
  run: cd ${{ env.APP_DIR }} && npm run test -- src/**/__tests__/a11y.test.tsx
```

## 5. How to add a new a11y test

### 5.1 Template

```tsx
import { describe, it, expect, afterEach, vi } from 'vitest';
import { render, screen, cleanup } from '@testing-library/react';
import { axe, toHaveNoViolations } from 'vitest-axe';
import { MemoryRouter } from 'react-router';
import MyPage from '../path/to/MyPage';

expect.extend(toHaveNoViolations);

// Mock hooks/contexts the page reads. Keep mocks minimal — see the
// existing a11y.test.tsx for the pattern (useApi, useAuth, react-i18next).

describe('MyPage accessibility', () => {
  afterEach(() => cleanup());

  it('has no axe-core violations', async () => {
    const { container } = render(
      <MemoryRouter initialEntries={['/path']}>
        <MyPage />
      </MemoryRouter>,
    );
    const results = await axe(container);
    expect(results).toHaveNoViolations();
  });

  it('exposes the semantic structure we ship', async () => {
    render(
      <MemoryRouter initialEntries={['/path']}>
        <MyPage />
      </MemoryRouter>,
    );
    // Example: a region landmark with an accessible name
    expect(
      screen.getByRole('region', { name: /order details/i }),
    ).toBeInTheDocument();
  });
});
```

### 5.2 Pre-merge checklist

- [ ] `npm run test:a11y` passes locally.
- [ ] No `vi.mock` of axe-core, no `disabledRules` arrays that hide real bugs.
  (`color-contrast` is the only rule we currently disable — see §6.)
- [ ] The page renders inside `<MemoryRouter>` (or a stub Provider) — we
  don't need a live Router, just a stable history.
- [ ] If you added a new role/aria attribute in the component, the test
  asserts it explicitly.
- [ ] If you changed i18n strings, the localized aria-label test still
  matches the prefix.
- [ ] Manual keyboard pass: tabbed through the screen, focus is visible,
  modals trap focus, Esc closes popovers.
- [ ] Linked this PR to a MASTER_PLAN task ID (e.g. P2-09, F.x, K.x).

## 6. Known limitations (intentional)

| Limitation                          | Why                                                       | Workaround                                |
|-------------------------------------|-----------------------------------------------------------|-------------------------------------------|
| `color-contrast` rule disabled      | happy-dom does not compute runtime contrast ratios; result is noise. | Track palette migration as a separate design-token task (P2/P3). |
| RTL + `dir="rtl"` rendering        | happy-dom has partial RTL support — visual layout is not asserted here. | Verify in Storybook / Playwright before shipping. |
| Live-region announcements           | axe-core cannot observe `aria-live` toasts reliably in jsdom. | Manual smoke test on staging. |
