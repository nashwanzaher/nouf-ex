# pgAdmin Server Registration Guide

> **Audience:** Developers setting up pgAdmin 4 to connect to the Nouf-ex development database.
> **Scope:** Best-practice, official PostgreSQL/pgAdmin procedure applied to this project.
> **Last reviewed:** 2026-07-04
> **Standards:** [PostgreSQL 17 docs](https://www.postgresql.org/docs/17/) · [pgAdmin 4 Server Dialog](https://www.pgadmin.org/docs/pgadmin4/latest/server_dialog.html)

---

## 1. Prerequisites

Before registering a server, confirm:

| Prerequisite | How to verify | Expected result |
|---|---|---|
| PostgreSQL 17 installed | `Get-Service postgresql-x64-17` | `Running` |
| Postgres listening on 5432 | `Test-NetConnection localhost -Port 5432` | `True` |
| `noufex_db` exists | `psql -U postgres -l` | `noufex_db` in list |
| Required roles exist | `psql -U postgres -c "\du"` | `postgres`, `noufex_app`, `noufex_owner`, `noufex_readonly` |
| Password encryption is SCRAM | `psql -U postgres -c "SHOW password_encryption;"` | `scram-sha-256` |

If any of these fail, see [§ 6 Troubleshooting](#6-troubleshooting).

## 2. Connection Roles (best practice: least privilege)

The project uses **role-based access control** (RBAC) per official PostgreSQL security guidance. Always connect with the most-privileged role you need for the task — never `postgres` for routine browsing.

| Role | Use case | Connects to | Permissions |
|---|---|---|---|
| `postgres` | One-time DDL, db:setup, role management | `postgres` or `noufex_db` | Superuser |
| **`noufex_app`** | **Recommended for daily browsing** | `noufex_db` | SELECT/INSERT/UPDATE/DELETE on 25 user-data tables |
| `noufex_owner` | Migrations, schema changes | `noufex_db` | Owns schema, DDL |
| `noufex_readonly` | BI / analytics | `noufex_db` | SELECT only |

> **Per official PostgreSQL guidance:** avoid using `postgres` for application access — it defeats the principle of least privilege. Connect with `noufex_app` for browsing the application's data.

## 3. Server Registration (UI step-by-step)

These steps match pgAdmin 4 v9.x and the official Server Dialog documentation.

### 3.1 Open the dialog

In the **Browser** panel:
1. Right-click **Servers**
2. **Register** → **Server...**

### 3.2 General tab

| Field | Value | Notes |
|---|---|---|
| Name | `NOUF-EX` | Friendly label shown in the tree |
| Server group | `Servers` (default) | Optional: group production/staging/dev |
| Comment | `Local dev — noufex_db` | Free-form, visible on hover |

### 3.3 Connection tab

| Field | Value | Why |
|---|---|---|
| Host name/address | `localhost` | Or `127.0.0.1` if DNS resolution is slow |
| Port | `5432` | PostgreSQL default |
| Maintenance database | `noufex_db` | NOT `nouf-ex_db` (hyphen vs underscore) |
| Username | `postgres` | For the superuser connection; or `noufex_app` for least-privilege |
| Password | `<your-password>` | See [§ 4 Credentials](#4-credentials) |
| Save password? | ☑ Yes (local only) | **Never enable on shared machines** — pgAdmin stores it in OS keyring |
| Role | *(blank)* | Optional: switch role after auth |
| Service | *(blank)* | Optional: pg_service.conf alias |
| Host address | *(blank)* | Optional: bypass DNS |
| Connection timeout | `10` (default) | ≥2 s per pgAdmin docs |

### 3.4 SSL tab

For **local development over loopback**, use:

| Field | Value | Why |
|---|---|---|
| SSL mode | `prefer` | Negotiate SSL; fall back to plain if unavailable |

For **production / remote**, use:

| Field | Value | Why |
|---|---|---|
| SSL mode | `require` | Force encryption (minimum for production) |
| Root certificate | `<path-to-ca.crt>` | Required for `verify-ca` / `verify-full` |

**Note:** local dev uses `prefer` because Postgres doesn't ship a CA cert out-of-the-box; loopback traffic is already inside the host's trust boundary.

### 3.5 SSH Tunnel tab

Leave **disabled** for local development. For remote DBs, configure an SSH bastion:
- Tunnel host: `bastion.example.com`
- Username: `deploy`
- Identity file: path to your private key

### 3.6 Advanced tab

Leave all defaults. The project's `.env` already encodes:
- `DB_POOL_MAX=20` (server-side, not a pgAdmin setting)
- `idle_in_transaction_session_timeout` etc. are server-side

### 3.7 Save

Click **Save**. The server appears under **Servers** in the Browser tree.

## 4. Credentials

This project ships **two sets** of credentials:

### 4.1 `postgres` (superuser — install-time)

Set during `postgresql-x64-17` Windows installer. Stored only in your head (and ideally in a password manager). **Never commit to git.**

```bash
# Verify from PowerShell (prompts for password)
psql -U postgres -h localhost -d postgres -c "SELECT version();"
```

### 4.2 `noufex_app` (runtime app user — auto-generated)

Generated by `scripts/db/db-setup.cjs` (idempotent on re-run) and stored in `.env`:

```bash
# From .env
DB_USER=noufex_app
DB_PASSWORD=<auto-generated 32-byte base64url>
DATABASE_URL=postgresql://noufex_app:<password>@localhost:5432/noufex_db
```

The `.env` file is **gitignored**. Regenerate with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

Then update both `DB_PASSWORD` and `DATABASE_URL` in `.env`, and re-run `npm run db:setup` (the script syncs the role's password to the new value via `CREATE ROLE ... IF NOT EXISTS`).

## 5. Verifying the connection

After saving the server, expand `NOUF-EX` → `Databases` → `noufex_db` → `Schemas` → `public` → `Tables`. You should see **35 tables**, including:

- `users` (12 rows in seed)
- `products` (24 rows in seed)
- `stores` (7 rows)
- `categories` (18 rows)
- `webhook_events` (0 rows; created by migration 0020)

Run a smoke test:

```sql
SELECT current_user, current_database(), version();
```

Expected output:
```
current_user | current_database | version
-------------+------------------+----------------------------------------
noufex_app   | noufex_db        | PostgreSQL 17.x on x86_64-windows, ...
```

For the superuser connection:
```sql
SELECT COUNT(*) AS migration_count FROM schema_migrations;
```
Expected: **22** (1 baseline + 21 incremental).

## 6. Troubleshooting

### 6.1 "password authentication failed"

**Cause:** Either the password is wrong, OR the user doesn't exist, OR `pg_hba.conf` requires `scram-sha-256` but the password is hashed with `md5`.

**Check password hash:**
```sql
SELECT rolname, rolpassword ~ '^SCRAM-SHA-256\$' AS is_scram
FROM pg_authid WHERE rolname IN ('postgres','noufex_app');
```

**If `is_scram` is false for `noufex_app`:**
```sql
-- As postgres superuser
ALTER USER noufex_app WITH PASSWORD '<new-password>';
```
Then update `.env` to match.

### 6.2 "could not connect to server"

**Cause:** Postgres not running, or wrong port.

**Check:**
```powershell
Get-Service postgresql-x64-17 | Select-Object Status
Test-NetConnection localhost -Port 5432 -InformationLevel Detailed
```

### 6.3 "database does not exist"

**Cause:** `noufex_db` was never created (or got dropped).

**Recreate:**
```bash
cd app
$env:DATABASE_URL = "postgresql://postgres:<your-pw>@localhost:5432/noufex_db"
npm run db:setup
```

### 6.4 SSL errors ("sslmode value 'require' invalid when SSL support is not compiled in")

**Cause:** pgAdmin's SSL mode is set to `require` but the server doesn't have SSL enabled.

**Fix (development):** change SSL mode to `prefer`.
**Fix (production):** configure Postgres with certificates — see [PostgreSQL SSL docs](https://www.postgresql.org/docs/current/ssl-tcp.html).

## 7. Best practices checklist (per PostgreSQL/pgAdmin official docs)

- [x] SCRAM-SHA-256 password hashing (PostgreSQL 14+ default)
- [x] `pg_hba.conf` restricts to localhost (no `0.0.0.0/0`)
- [x] Least-privilege role (`noufex_app`) used by app; `postgres` only for one-time DDL
- [x] Separate roles for migration owner (`noufex_owner`) and analytics (`noufex_readonly`)
- [x] No passwords stored in code (all in `.env` or install-time)
- [x] `.env` gitignored
- [x] Connection timeout ≥ 2 seconds (default 10)
- [x] SSL mode appropriate for environment (`prefer` local, `require`/`verify-full` production)
